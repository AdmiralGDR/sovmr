# sovmr — суверенный перекодировщик медиа

Визуально без потерь, с ускорением на GPU — **пакетное сжатие видео** для
Linux и Windows (сделано под Pop!_OS / COSMIC, кросс-собрано для Windows
x86_64). Бросаете папки с MP4 или MKV на вход — получаете fast-start AV1
(или HEVC) во много раз меньшего размера, **с сохранением контейнера**: MP4
остаётся MP4, Matroska остаётся Matroska со всеми звуковыми дорожками,
главами и тегами, на полностью суверенном zero-copy конвейере NVDEC→NVENC
на RTX-видеокартах (**никакого FFmpeg нигде**), с очередью, которая
переживает паузы, защищает от потерь поколения и никогда не оставляет
недописанных файлов.

Лицензия **AGPL-3.0-or-later**. Собрано с нулевыми сторонними зависимостями,
кроме одного санкционированного исключения (`egui` для графического
интерфейса).

## Быстрый старт

```sh
make            # оптимизированная сборка + запуск GUI
make mock       # режим симуляции: полная демонстрация UI без GPU
make report     # проверка оборудования без окна
make install    # закрепить в лаунчере + пункт «Compress with sovmr»
make package    # единый файл dist/sovmr-x86_64.AppImage (движок внутри)
make test       # юнит- и doc-тесты воркспейса
make e2e        # сквозной тест кодирования на реальном GPU
```

## Как добавить файлы (три гарантированных способа)

1. **Кнопка «➕ Добавить медиа…»** — открывает собственный диалог выбора
   файлов рабочего стола (`zenity`, запасной `kdialog`) через
   `std::process::Command`. Работает в любом окружении Linux, включая
   Wayland.
2. **Командная строка / файловый менеджер** — `sovmr FILE...` (пункт
   правого клика «Compress with sovmr» использует этот путь).
3. **Перетаскивание** — на сессиях X11 работает «из коробки». В Wayland
   вышестоящий `winit` пока не реализует перетаскивание; запустите с
   `sovmr --x11`, чтобы работать в XWayland, где перетаскивание доступно.
   Зона сброса сообщает об этом, а не молчит, и каждый отклонённый сброс
   печатает подробную причину в stderr.

Попытки приёма файлов и результаты конвейера также пишутся в
`~/.local/state/sovmr/sovmr.log` (суверенный логгер, без крейтов).

## Структура воркспейса

| Крейт | Зависит от | Назначение |
|---|---|---|
| `sovmr-core` | *ни от чего* (только std, навсегда) | Модель задания, валидированные настройки, врата враждебного ввода, планировщик оборудования и безмьютексный движок пакетной обработки на передаче сообщений. Владеет фасадом `EncoderProvider`, который реализует каждый бэкенд. |
| `sovmr-os` | *ни от чего* (даже без `libc`) | Суверенная граница платформы — **каждый** системный вызов проекта живёт здесь: вручную объявленный загрузчик `dlopen`/`dlsym` за RAII-типом `Library`, отображение файлов в память, проверка свободного места, обработка сигналов и интеграция с рабочим столом (выбор файлов, запрет сна, уведомления, сохранённые предпочтения) — один платформенно-нейтральный интерфейс на концерн, Linux и Windows за одними и теми же сигнатурами. |
| `sovmr-cuda` | `sovmr-os` | Минимальный мост к CUDA Driver API (`libcuda.so.1`): `cuInit`, поиск устройства, RAII-контексты, символьные ошибки от драйвера. |
| `sovmr-nvenc` | `sovmr-os`, `sovmr-cuda` | Аппаратное кодирование: версионированная таблица функций NVENC через `NvEncodeAPICreateInstance`, сессии кодирования **AV1 и HEVC** на суверенных CUDA-контекстах, RAII-регистрация VRAM, символьные ошибки `NVENCSTATUS`. |
| `sovmr-nvdec` | `sovmr-os`, `sovmr-cuda` | Аппаратное декодирование (`libnvcuvid.so.1`): входная сторона zero-copy VRAM-конвейера (см. `docs/zero-copy-pipeline.md`). |
| `sovmr-mp4` | *ни от чего* (`#![forbid(unsafe_code)]`) | Строгий zero-copy инструментарий ISOBMFF: парсер боксов, A/V-демуксер с полным таймингом PTS/DTS, факты битстрима HEVC и fast-start муксер **AV1/HEVC** (`moov` перед `mdat`, побайтовый passthrough `mp4a`). |
| `sovmr-mkv` | `sovmr-mp4` | Суверенная Matroska: EBML-читатель, демуксер и муксер — переносит видео, **каждую звуковую дорожку**, главы, заголовок и теги, ноль зависимостей. |
| `sovmr-audio` | *ни от чего* | Суверенный звук: декодеры без потерь и энкодер AAC-LC, ноль зависимостей. |
| `sovmr-native` | все GPU-мосты + `sovmr-core` + `sovmr-mp4`/`sovmr-mkv`/`sovmr-audio` | **САМ движок**: демукс → NVDEC → VRAM → NVENC → fast-start **MP4 или Matroska**, нулевые копии, безблокировочный кэш регистраций VRAM, как `NvencNativeProvider`. |
| `sovmr-ui` | `sovmr-core`, `sovmr-os`, `egui` | Переиспользуемая оболочка-панель: чистый редьюсер событий, обобщённый мост каналов, оформленное окно egui, **интерфейс на английском/русском**. Ничего не знает о FFmpeg или NVIDIA. |
| `sovmr-app` | всё вышеперечисленное | Корень композиции (единственный крейт, видящий все части): детекция оборудования, конвейер приёма, интеграция с рабочим столом, точка входа CLI/файлового менеджера. |
| `sovmr-setup` | *бинарник приложения (встроен на этапе сборки)* | Суверенный установщик для Windows: один самодостаточный исполняемый файл, который устанавливает, обновляет и удаляет sovmr. |

Стрелки зависимостей указывают только влево; `sovmr-ui` и бэкенды никогда не
видят друг друга. Смена движка кодирования — одна строка в `sovmr-app`.

## Гарантии дизайна

- **ACID-очередь** — одно задание есть атомарная единица: выходные файлы
  появляются только через переименование на той же файловой системе;
  отмена/сбой удаляет `.part`; **Пауза** никогда не убивает идущее
  кодирование (невозобновляемая работа не выбрасывается).
- **Умный пропуск** — источники, уже в целевом кодеке ниже 1.5 б/(пкс·с),
  помечаются «уже оптимально» вместо ухудшения бессмысленным
  перекодированием.
- **Враждебный ввод** — магические байты контейнера проверяются заранее, а
  суверенный демуксер не доверяет ни одному полю размера и счётчику таблиц
  (типизированные ошибки, никогда не паники); вывод драйвера и телеметрия
  тоже разбираются защитно.
- **Суверенная интеграция с рабочим столом** — уведомления через
  `notify-send` или сырой `gdbus`, запрет сна через `systemd-inhibit`,
  счётчик GPU через `nvidia-smi`: везде `std::process::Command`, без
  клиентских крейтов.
- **Готовый для веба вывод** — муксер пишет fast-start MP4 (`moov` перед
  `mdat`) с побайтово скопированным звуком источника, чередуя по временным
  меткам.
- **Экономный к батарее UI** — перерисовки планируются только пока идёт
  кодирование; иначе окно спит, пока его не разбудит событие движка.

## Переносимость

`make package` создаёт `dist/sovmr-x86_64.AppImage` — единый маленький файл,
содержащий ровно один бинарник. Движку не нужны никакие внешние программы:
он `dlopen`-ит собственные библиотеки драйвера NVIDIA (`libcuda.so.1`,
`libnvcuvid.so.1`, `libnvidia-encode.so.1`) во время выполнения, так что
образ работает на голой машине, где не установлено ничего, кроме драйвера
NVIDIA.

На Windows тот же движок поставляется через `sovmr-setup` (`make windows`) —
один самодостаточный установщик, который несёт программу внутри себя и так
же во время выполнения разрешает собственные DLL драйвера (`nvcuda.dll`,
`nvcuvid.dll`, `nvEncodeAPI64.dll`).

## Требования

- Linux x86_64 с дисплеем (Wayland или X11) либо Windows x86_64.
- GPU NVIDIA + драйвер для аппаратного кодирования (AV1 требует RTX
  40-й серии или новее; более старые RTX/GTX откатываются на HEVC). Режим
  `--mock` запускает весь UI на любой машине, с GPU или без.
